# 從資料取得到深度詰問：Ling-Ling 分析工作流 Best Practice

這份教學指南將帶您了解如何最大化利用 Ling-Ling（特別是 Phase 5 與 Phase 6 引入的動態規劃與執行能力），打造一套從「取得文本」到「批判分析」的高效工作流。

---

## 1. 核心概念：資料取得 (Load Sources)

Ling-Ling 的強項在於它能直接讀取您 Vault 裡的真實筆記，確保分析是「基於事實」而非 LLM 的幻覺。

* **最佳實踐**：永遠使用 `[[雙方括號]]` 來標註您想分析的目標文章。
* **底層機制**：當系統看到 `[[文章標題]]`，它會透過內建的 `load_sources` (或 `vault.load_sources`) 自動去讀取該檔案的 Markdown 完整內容，並作為後續分析的基礎輸入。

---

## 2. 動態編排：分析與詰問 (Insight Planner Mode)

有時候您需要的不是單一的總結，而是「先讀取資料 ➡️ 進行批判性比對 ➡️ 最後產出行動指引」的多步驟流程。這時請愛用最新的 **Planner Mode**。

### 步驟一：安全預覽 (Preview)
在不耗費大量 API Token 的前提下，先讓系統為您規劃分析腳本。
> **語法**：`@ling-insight planner-mode [您的複雜需求]`

**範例**：
```text
@ling-insight planner-mode 請幫我比對 [[2026科技趨勢]] 與 [[AI產業觀察]]，從批判角度分析兩者觀點的矛盾處，並給出行動建議。
```
系統會產出一份 `🎐insight-plan-xxxx.md` 報告。點開後，您會看到系統已經為您設計好了完美的工作流（通常是：1. 載入來源 -> 2. 詰問 critique -> 3. 綜合hesize）。

### 步驟二：正式執行 (Execute)
若您覺得系統規劃的步驟很完美，只需加上 `/execute`，系統就會掛載 Executor 引擎替您跑完全程：
> **語法**：`@ling-insight planner-mode /execute [您的複雜需求]`

系統會自動完成所有中介步驟的傳遞，最終將一份深度、經過詰問的綜合報告呈現在您眼前。

---

## 3. 直接指令：單點突破 (Targeted Insight)

如果您只是想對單一或多篇指定文章進行特定手法的分析，可以直接呼叫虎之卷裡的指令：

* **深度隨機碰撞**：
  使用 `/montecarlo [[文章A]] [[文章B]]` 來強制系統從高創意的角度去尋找這兩篇文章之間潛在的、非直觀的深層連結。
* **特定格式產出**：
  使用 `/template:tech-rpt [[文章A]]` 強制以技術報告的嚴謹格式來解析該文章。

---

## 4. 寫作與提示詞技巧 (Prompting Tips)

要讓 Ling-Ling 產出最高品質的批判 (Critique) 與分析，請掌握以下訣竅：

1. **明確指定焦點 (Focus)**
   與其說「請分析這兩篇」，不如說「請比較這兩篇，並**著重在『實作成本』與『維護難度』的差異進行批判**」。給予明確的 Focus 能讓 `llm.critique` 發揮最大的效用。
2. **避免直接貼上長文**
   不要在對話框貼上幾千字的文章。請先將文章存成 Vault 裡的一則筆記（如 `新技術評估.md`），然後用 `[[新技術評估]]` 呼叫它。這不但能保持對話視窗整潔，也能在日後輕易被 RAG 檢索到。
3. **將複雜任務交給 Planner**
   當您發現自己需要在腦中拆解任務時（例如：我要先找出A的重點，再對比B的重點，再寫成大綱...），直接使用 `@ling-insight planner-mode /execute`，讓系統的規劃大腦代勞。

# 🔭 @ling-scout 範例指令

叫 Scout 立刻出門偵查一趟——爬 `Scripture/Scout.md` 目標清單裡的網站
（GitHub Trending、Hacker News、arXiv、任何有 RSS 的站），逐條讀內文、
用你的語言寫分析，整理成一份日報。

> [!TIP]
> **發動方式**：把這個檔案直接拖進 `toLingLing/`（不需要參數）。
> 報告寫入 `fromLingLing/✅Scout-YYYY-MM-DD.md`，並鏡射到 `Notes/Scout/`
> 讓日報可被 RAG 檢索。夜間排程（`scout: true` 時）跑的是同一條路，
> 這個指令**不受開關限制**、隨時可用。

---

## 最簡單：拖檔即可
```markdown
@ling-scout
```
或斜線寫法：
```markdown
/scout
```

### 日報內容
1. **各來源逐條分析**：每條新項目抓回頁面內文，2-4 句有根據的概要
   （不是標題改寫），以 Scripture `say` 指定的語言輸出。
2. **🔁 持續上榜**：連續 ≥3 天掛在榜上的項目標註天數（榜單型來源如
   GitHub Trending 才有）。
3. **相關筆記**：某條項目與 vault 既有筆記高度相關時，行尾附
   `相關筆記: [[筆記名]]`。
4. **🧹 抓取狀況**：每個目標抓了幾項、幾項是新的；失敗的目標附原因，
   不影響其他目標。

### 注意
- **去重狀態與夜間排程共用**（30 天窗口）：白天手動跑過，晚上的排程就
  只剩少量新項目——這是正常現象，不是壞掉。
- 每條新項目 = 一次網頁抓取＋一次 LLM 呼叫；新項目多的時候（例如第一次跑）
  會花上一段時間，Scout 會安靜地做完。
- 抓不到內文的條目（付費牆、擋爬蟲的站）會標「（未取得內文，僅依標題與
  摘錄分析）」；同一個站連續失敗 3 次會安靜跳過 7 天，不再浪費時間。
- **中斷安全**：daemon 中途重啟的話，這一輪什麼都不會被標成「已看過」，
  下次重跑會完整重來——項目絕不會被吞掉。
- 目標清單、語言、每站上限都在 `Scripture/Scout.md` 的表格裡改，
  行為旋鈕（`scout_fetch_content` / `scout_bridging` / `scout_mirror`）
  在 `Scripture.md`。

### 搭配使用
日報裡看到有意思的條目，把網址丟給 [[toranomaki/@ling-dig]] 深挖一層——讀完主頁、
跟進值得跟的連結，寫成一篇深掘筆記。

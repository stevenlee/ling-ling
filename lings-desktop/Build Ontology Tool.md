# 給小學生的 Ontology 編輯器與視覺化工具：研究與建議報告

  

> 主題：是否該找現有工具或自行開發一套適合小學生的 Ontology 工具，以及 Ontology 對學習者的好處

> 撰寫日期：2026 年 6 月

> 重點：自建 vs 採用建議、教育效益與理論依據、設計與實作建議

  

---

  

## 一、核心結論（先講重點）

  

1. **不要給小學生「正式的」Ontology 編輯器（如 Protégé／OWL）。** 那是給知識工程師用的形式化工具，學習曲線陡、語意負擔重，與小學生的認知發展不匹配。

2. **小學生真正需要的是「概念圖（Concept Map）」工具**——也就是 Ontology 的教育學前身與簡化版：節點代表概念、有標籤的連線代表關係。這正是 Ontology 最有教育價值的核心，且早有兒童適用的工具。

3. **建議「先採用、再客製」的混合策略**：以現成概念圖工具（如 Kidspiration、Popplet、CmapTools）做教學試點，若有課綱整合、繁體中文介面、資料隱私、教師後台等特殊需求，再以開源圖形函式庫（Cytoscape.js／React Flow）打造輕量自建層，而非從零開發完整本體論編輯器。

4. **Ontology／概念圖對學習者的最大好處是促進「有意義學習」（meaningful learning）**：把新知識連結到既有認知結構、外化思考、發現迷思概念、培養後設認知，而非死記硬背。

## 二、Ontology 與概念圖：先釐清概念層次

  

「Ontology（本體論／本體）」在資訊科學中指對某個領域的概念、屬性與彼此關係所做的形式化、可被機器處理的明確描述（常以 OWL/RDF 表示）。它強調**邏輯一致性、可推理、可被電腦運算**。但對教學現場而言，需要把它降階為三個由淺到深的層次：

| 層次              | 形式                   | 關係標籤             | 嚴謹度 | 適合對象      |
| --------------- | -------------------- | ---------------- | --- | --------- |
| 心智圖 Mind Map    | 單一中心向外發散的樹狀          | 多半無標籤            | 低   | 低年級、發想    |
| 概念圖 Concept Map | 多中心、節點＋**有標籤連線**形成命題 | 有（如「造成」「需要」「屬於」） | 中   | 中高年級、學科學習 |
| 形式化本體論 Ontology | 類別／屬性／公理，可機器推理       | 嚴格、可運算           | 高   | 大學以上、知識工程 |

  

**對小學生，目標應落在「概念圖」這一層。** 概念圖由教育學者 Joseph Novak 於 1970 年代在康乃爾大學提出，本就是為了表徵學生科學知識而設計；它與本體論共享「節點—關係」的知識圖譜本質，但保留了學習所需的彈性與直覺。維基百科亦明確指出：概念圖「可被視為建構本體論的第一步」，且「Novak 曾教導年僅六歲的孩子製作概念圖」。換言之，**概念圖是把 Ontology 思維帶給兒童最自然、且有實證基礎的途徑。**

## 三、Ontology／概念圖對學習者的好處

  

### 1. 促進「有意義學習」而非機械記憶

理論根基是 David Ausubel 的認知學習理論：**「影響學習最重要的單一因素，是學習者已經知道什麼。」** 概念圖強迫學習者把新概念「掛」到既有的認知結構上，形成命題（如「水→會→蒸發」），這正是有意義學習的核心機制，與背誦零散事實截然不同。

  

### 2. 外化思考、看見自己的理解

McAleese 提出「知識競技場（knowledge arena）」概念：把知識用節點與關係明確畫出來，學習者就能**察覺自己知道什麼、不知道什麼**，進而修正。對小學生而言，這把抽象的「理解」變成看得見、可操作的物件。

  

### 3. 培養後設認知（learning to learn）

畫概念圖的過程本身就是「思考自己的思考」。Maria Birbili 將此應用於幼兒教育，證實**即使年幼的孩子也能藉概念圖學會反思自己所知**，是培養終身學習者的基礎能力。

  

### 4. 揭露並矯正迷思概念

當學生把「鯨魚→是一種→魚」這類連線畫出來，教師能立即看見錯誤的概念連結並針對性教學。概念圖因此是極佳的**形成性評量工具**——評的是「概念之間的關係」而非單點記憶。

  

### 5. 視覺＋語文雙重編碼，降低認知負荷

依雙重編碼理論（Paivio），同時用圖像與文字呈現知識能強化記憶與理解。圖形化的關係結構也降低工作記憶負擔，特別有利於閱讀能力仍在發展、或語言學習中的兒童。

  

### 6. 支援語言發展與表達

為連線命名（「因為」「屬於」「需要」）的過程，要求學生用精確的詞彙描述關係，**同時鍛鍊語言能力與邏輯推理**。

  

### 7. 促進合作學習與創造力

多人共建概念圖能形成「共享理解」，也常被用於腦力激盪。多中心、自由形式的結構鼓勵學生建立新的概念連結，激發創造力。

  

> 小結：對學習者而言，Ontology 的價值不在「機器能不能推理」，而在於它把「知識是一張關係網」這件事變得可見、可操作、可討論——這恰好是建構主義學習觀的具體實踐。

## 四、現有工具盤點（依適用對象分層）

  

### A. 形式化本體論編輯器 —— ❌ 不適合小學生

| 工具                                 | 說明                       | 為何不適合                        |
| ---------------------------------- | ------------------------ | ---------------------------- |
| **Protégé / WebProtégé**（Stanford） | 業界標準 OWL/RDF 本體論編輯器，免費開源 | 介面以類別/屬性/公理為中心，術語艱深，為知識工程師設計 |
| **WebVOWL**                        | 將 OWL 本體論視覺化的網頁工具        | 是「閱讀檢視」工具而非兒童創作工具，符號體系專業     |
| **TopBraid、PoolParty**             | 企業級本體論／分類法平台             | 商業、複雜、昂貴                     |

  

這類工具強調嚴謹與可推理，**對小學生而言負擔遠大於效益**，不建議直接使用，至多作為教師理解「完整 Ontology 長什麼樣」的參考。

  

### B. 兒童／教育導向的概念圖工具 —— ✅ 建議優先採用

| 工具 | 特性 | 適用性 |
|------|------|--------|
| **Kidspiration / Inspiration**（Inspiration Software） | 專為 K-5 視覺學習設計，圖片符號庫、語音支援、圖文切換 | ⭐ 最貼合低中年級；商業付費 |
| **CmapTools / Cmap**（IHMC，Novak 團隊） | 概念圖理論發源工具，免費，支援命題式連線、可共享 | ⭐ 中高年級與教師；功能完整 |
| **Popplet** | 觸控友善、支援圖片與手寫，介面活潑 | ⭐ 平板教學、低年級友善；付費 |
| **MindMup、Coggle、bubbl.us** | 免費／freemium 線上心智圖與概念圖 | 介面簡潔、易上手；偏心智圖 |

  

### C. 通用圖形／知識圖譜視覺化工具 —— △ 可作自建基礎

| 工具/函式庫                                    | 用途           | 備註                     |
| ----------------------------------------- | ------------ | ---------------------- |
| **Miro、Lucidchart**                       | 通用協作白板與圖表    | 功能強但非兒童專用，授權成本高        |
| **Kumu、Gephi、Neo4j Bloom**                | 關係網路／知識圖譜視覺化 | 偏資料分析，過於專業             |
| **Cytoscape.js、D3.js、React Flow、JointJS** | 開源圖形繪製函式庫    | 不是成品，但**是自建時最務實的技術底座** |

## 五、自建 vs 採用：分析與建議

### 評估維度

| 維度              | 採用現成工具                     | 自行開發                     |
| --------------- | -------------------------- | ------------------------ |
| **成本**          | 低（多為免費或低價訂閱）               | 高（設計、開發、測試、長期維護）         |
| **上線速度**        | 立即可用                       | 數月起跳                     |
| **兒童適用性**       | Kidspiration／Popplet 已高度優化 | 可完全客製，但需自行驗證             |
| **繁體中文／在地課綱**   | 介面與內容未必貼合台灣課綱              | 可完全在地化                   |
| **資料隱私／法遵**     | 受第三方政策約束，兒童資料外流風險          | 可自行掌控（符合個資法／COPPA／FERPA） |
| **教師後台／評量整合**   | 多半有限                       | 可深度整合學校系統                |
| **客製化關係標籤、遊戲化** | 受限於產品                      | 完全自由                     |

  

### 建議：採三階段「先採用、後客製」混合策略

  

**階段一（0–3 個月）：直接採用，驗證教學設計。**

先用 **Kidspiration（低年級）或 CmapTools（中高年級）** 進行教學試點。重點不在工具，而在**先確認「概念圖教學法」對你的學生與課綱真的有效**，並蒐集教師回饋。此階段幾乎零開發成本。

  

**階段二（並行評估）：判斷是否有「非自建不可」的理由。**

若出現以下需求，才值得投入自建：

- 需要**繁體中文、貼合台灣課綱**的概念與模板；

- 需要**嚴格的兒童資料隱私控管**（資料留在校內／符合個資法）；

- 需要**教師後台、自動評量、學習歷程**整合；

- 需要**遊戲化、語音、無障礙**等特殊體驗。

若都不需要，就停在採用階段——**自建一套完整本體論編輯器對小學情境而言通常是過度工程。**

  

**階段三（如確需自建）：站在開源肩膀上，做「薄」的客製層。**

不要從零造圖形引擎，更不要做成 OWL 編輯器。改以 **React Flow 或 Cytoscape.js** 作為畫布底座，只開發「兒童友善的互動層＋教師後台」。這能把開發量降到可控，同時保有完全的在地化與隱私掌控。

  

> 一句話建議：**先採用現成概念圖工具做教學試點；只有在隱私、在地化或教師後台有硬需求時，才以開源函式庫打造輕量自建版——絕不要為小學生開發正式的 OWL 本體論編輯器。**

## 六、若要自建：設計與實作建議

  

### 設計原則（兒童導向 UI/UX）

  

1. **降階知識模型**：只保留「概念節點＋有標籤連線」，隱藏類別/公理/推理等形式化概念。內部資料可仍以圖（graph）結構儲存，為未來升級保留空間。

2. **拖放與觸控優先**：以平板觸控為主要場景，大按鈕、大字、可手指拖曳；避免依賴右鍵與快捷鍵。

3. **圖像化節點**：提供主題式圖示／貼圖庫（動物、植物、天氣……），讓不擅文字的孩子也能表達概念（呼應雙重編碼）。

4. **預設關係標籤**：提供少量精選的關係詞下拉選單（「是一種」「會」「需要」「住在」「造成」），降低語言負擔並引導正確命題；高年級可自訂。

5. **鷹架與範本**：提供半完成的概念圖、引導性焦點問題（如「什麼是水？」），讓學生填空式起步。

6. **即時、非懲罰式回饋**：用顏色、動畫鼓勵連結，而非標紅打叉；錯誤連結作為師生討論素材。

7. **語音與無障礙**：朗讀節點文字、語音輸入、色盲友善配色，符合無障礙規範。

8. **自動儲存與復原**：兒童容易誤操作，需有 undo／autosave，降低挫折。

9. **遊戲化（適度）**：徽章、主題關卡可提升動機，但避免喧賓奪主、避免過度競爭。

10. **教師視圖**：教師端可瀏覽全班概念圖、快速辨識共通迷思概念、匯出評量。

  

### 技術架構建議

  

- **前端**：Web（React）＋ **React Flow** 或 **Cytoscape.js** 作為圖形畫布；以平板瀏覽器為主要目標，採響應式／PWA。

- **資料模型**：以 JSON 儲存節點與邊（node/edge），結構上向 RDF 三元組（主詞-關係-受詞）看齊，方便日後匯出或升級為較形式化的表示。

- **後端／儲存**：輕量後端（如 Node + PostgreSQL，或校內部署）。**兒童資料最小化蒐集**，可考慮資料留在本地／校內。

- **匯出**：支援 PNG/PDF（給家長、做評量）與結構化格式（JSON/CSV），保留資料可攜性。

- **法遵**：遵循台灣個資法；若面向國際，留意美國 **COPPA**（兒童線上隱私）與 **FERPA**（學生紀錄）。預設不投放廣告、不做行為追蹤。

## 七、給決策者的行動清單

  

1. **本學期**：選 Kidspiration 或 CmapTools，在 1–2 個班級做概念圖教學試點，設計 3–5 堂課與前後測。

2. **同步**：盤點隱私、在地化、教師後台是否為硬需求，作為「是否自建」的決策依據。

3. **試點後**：若教學成效獲驗證且確有客製需求，再啟動以 React Flow／Cytoscape.js 為底座的輕量自建專案；否則持續採用現成工具。

4. **長期**：把焦點放在「概念圖教學法」的師資培育與課程設計上——工具只是載體，**教學設計才是學習成效的決定因素**。
